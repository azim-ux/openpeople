# Public release and account recovery contract

## Core HR release contract — 0.8.0

Deliver a process-selected `core-hr` product profile and executable installation/endpoint/recovery acceptance. Core HR owns people, direct reporting relationships, compensation records, leave/attendance/checklists, core reports, notifications, security and backups. Authentication and individual HR/manager/employee/auditor authorisation remain enforced. Broader modules and report/role/policy bypasses are denied before idempotency replay. Existing data is retained. Production defaults to Core HR; changing scope requires an operator-controlled process restart. No HTTP action can enable payroll.

Installation evidence must be read-only and scoped to an explicit stopped workspace. Recovery must target a new directory, privately prompt for the passphrase, match a frozen independently retained business-data fingerprint and audit anchor, remove reusable authentication state, and report bounded restoration time. Evidence files are created exclusively with 0600 permissions in a 0700 directory. Do not claim physical custody or remote-network acceptance from same-computer tests. Bootstrap credentials belong to the installing operator, not the software author. No personal files or OS settings may be changed by validation.

Implementation handoff: direct implementation and protected regression/browser/package/service drills. Actual separate-device custody, host encryption, reboot operation, privacy acceptance and independent review remain installation evidence, not mocked product capabilities. See [Core HR acceptance](CORE_HR_RELEASE.md).

The deliverable is generic software that organisations can install themselves. Building, testing and publishing source requires no personal email, administrator account, password or cloud account from the author. The existing local demonstration workspace stays unconfigured. An installer may use `admin@openpeople.invalid` as a local login identifier; it does not send email.

This implementation adds an operator-only interactive bootstrap, single-use MFA recovery codes and a source-only public GitHub package with CI. Bootstrap must validate a password and a real current authenticator code before inserting an administrator, require MFA, create no samples or sessions, and refuse a configured workspace. Secrets are prompted privately and never accepted as command arguments. Temporary enrollment material is created exclusively with private permissions and removed on success, failure or interruption. Backup configuration and technical production checks remain separate explicit installation steps.

Recovery codes require recent, fully verified authentication plus a fresh authenticator proof to generate. Only hashes are stored, codes are disclosed once, replacements invalidate previous codes, and use atomically consumes a code and revokes other sessions. Password reset invalidates codes; backups and restores remove codes so an old archive cannot resurrect a spent code. Invalid proofs, CSRF, stale sessions and disabled accounts must fail without consuming a valid code. Audit records must omit codes and authenticator secrets.

Public packaging uses an allowlist. It excludes runtime databases, keys, setup tokens, recovery material, service accounts, test logs and local operational evidence. Tests use fictional records in disposable OS-sandboxed workspaces and do not modify personal files. GitHub CI is supplied; remote CI execution is not claimed before an actual upload.

These additions do not certify complete statutory payroll, authority transmission, all countries' laws, SCIM/SAML, high availability or actual off-device storage. Native Workday payroll itself is country-specific with third-party providers for other jurisdictions. Each implemented tax module and filing format must retain its documented scope. Government submissions require official schemas, reviewed employer data, credentials and authority acceptance; a fabricated response or operator checkbox is not acceptance. Off-device recovery requires independent storage, which is unavailable in this installation.
